# Серверный API v1

База: `https://revoulce.ftp.sh/ehvk/api/v1`. Каждый пользовательский запрос, включая получение изображения, требует `Authorization: Bearer <API-токен>`. Cookies E-Hentai и токен VK в API не передаются. Исключение — `/ehvk/health/live` и `/ehvk/health/ready`, возвращающие только `status`.

Ответ ошибки:

```json
{
  "code": "VERSION_CONFLICT",
  "message": "Предпросмотр изменён. Получите актуальную версию.",
  "retryable": false,
  "request_id": "9c4f4151-442e-40a3-8e14-c6220c6ff44c"
}
```

Версия JSON-контракта входит в URL. Runtime-схемы запросов находятся в `src/shared/contracts.ts`. Поля, не входящие в схему, отвергаются. ID черновиков, файлов и задач — UUID, созданные сервером.

## Подключение VK

`GET /status` включает `vk.verified`, `vk.authorizationBlocked`, `vk.state` и при наличии `vk.code`, `vk.groupId`, `vk.groupName`, `vk.groupUrl`. Секреты и пути файлов токенов не возвращаются. Состояния: `integration_required` (нет конфигурации), `authorization_required`, `donut_verification_required`, `privacy_verification_required`, `temporary_error`, `verification_required`, `group_mismatch`, `ready`.

`POST /vk/check` без тела повторяет чтение пользовательских прав, ID владельца токена, целевой группы, постоянного Donut и адреса загрузки фото; возвращает тот же формат, что `/status`. Фотографии и посты не создаются. Успешная проверка снимает сохранённую блокировку авторизации, но не повторяет задачи и не запускает очередь немедленно. При работе обработчика — `409 WORKER_BUSY`. Требуется API-токен владельца. Настройка: [vk.md](vk.md).

Дополнительная диагностика: `vk.apiErrorCode` — числовой код ошибки VK; `vk.donutReference` — `postId` и, после чтения, `found`, `isDonut`, `paidDuration`, `durationSource` (`api` или `owner_confirmation`). Содержимое записи, исходные внешние ошибки и токены не возвращаются. Причины отклонения Donut-поста и подтверждение владельцем при отсутствующем сроке перечислены в [vk.md](vk.md).

## Подготовка

`POST /drafts` → `201`: создать черновик и выбрать страницы.

```json
{
  "galleryUrl": "https://e-hentai.org/g/123/abcdef1234/",
  "title": "Название галереи",
  "pageCount": 14,
  "tags": {
    "parody": ["Kill la Kill"],
    "character": ["Ryuko Matoi", "Nui Harime"],
    "cosplayer": ["Kate Sarkissian"]
  }
}
```

Допустим только канонический HTTPS URL E-Hentai с завершающим `/`, положительным gallery ID и десятисимвольным hex-токеном. `pageCount`: 13–1 000 000. Сервер проверяет структуру заявленных метаданных; их соответствие сайту обеспечивает браузерный адаптер. Внешних запросов за галереей сервер не делает.

Ответ содержит `id`, `version: 1`, `state: preparing`, `gallery`, `fields`, `texts`, `assets`, `duplicates`, `replacementAvailable`. `assets` содержит четыре записи `role: public` и девять `role: donut`, отсортированные по странице внутри роли. Для каждой записи есть `id`, `page`, `state`, `position`, свойства файла и `previewUrl`. Для отображения используйте порядок массива и `page`; после замены исходная `position` может отличаться от порядка страниц.

`GET /drafts/{id}` возвращает текущий черновик. `PATCH /drafts/{id}` принимает ожидаемую `version` и поля целиком и/или `replaceAssetId`:

```json
{
  "version": 1,
  "fields": {
    "fandom": ["Kill la Kill"],
    "character": ["Ryuko Matoi"],
    "model": ["Имя модели вручную"],
    "includeModel": true
  }
}
```

`replaceAssetId` заменяет соответствующую страницу случайной свободной страницей; создаётся новый asset ID, новый файл нужно загрузить отдельно. Замена исключает все 13 текущих страниц, включая старую. При ровно 13 страницах ответ `409 NO_REPLACEMENT`. Старые запросы получают `409 VERSION_CONFLICT`. Подтверждённый черновик менять нельзя.

`PUT /drafts/{id}/assets/{assetId}` передаёт **сырые байты одного файла**, без multipart, base64 и URL. Заголовки:

```http
Authorization: Bearer <токен>
Content-Type: application/octet-stream
If-Match: "1"
X-Source-Kind: page
```

`If-Match` содержит текущую версию в двойных кавычках. `X-Source-Kind` — `page` или `free_original`; по умолчанию `page`. Эта отметка приходит из браузера; сервер не может проверить стоимость исходной загрузки. `gpSpendingAllowed` всегда `false`.

Сервер проверяет содержимое независимо от MIME-заголовка. Поддержаны статические JPEG, PNG, WebP, GIF и AVIF; входной и итоговый лимит — 50 МиБ, декодирование до 40 мегапикселей. JPEG/PNG сохраняются без изменения байтов. WebP/GIF/AVIF преобразуются в PNG до предпросмотра, без уменьшения размеров; ориентация применяется к итоговому файлу. Анимация и многостраничные файлы требуют замены (`ANIMATION_UNSUPPORTED`). Один файл обрабатывается за раз; при занятом обработчике — `409 UPLOAD_BUSY`. Квота или свободный диск — `507 STORAGE_QUOTA`, включая исходник и результат преобразования. Дубли по исходному/итоговому SHA-256 — `409 DUPLICATE_IMAGE`. Неуспешная загрузка не изменяет версию и не создаёт готового файла.

Карточка содержит итоговые `mime`, `width`, `height`, `bytes`, `final_sha256`, исходные `source_mime`, `source_width`, `source_height`, `source_bytes`, `source_sha256` и булевый `transformed`. Серверные пути обоих файлов не выдаются. Оба файла сохраняются и удаляются по срокам хранения; для JPEG/PNG хранится одна копия. `/status.limits.acceptedFormats` перечисляет входные форматы, `outputFormats` — итоговые.

Каждая успешная загрузка увеличивает версию и возвращает **весь обновлённый черновик**. Поэтому загружайте последовательно с версией предыдущего ответа. Если черновик изменён во время загрузки, итоговый файл отвергается. После всех 13 файлов статус `ready`; повторное получение этого черновика даёт точный итоговый предпросмотр.

`GET /assets/{id}/preview` возвращает защищённый JPEG/PNG с `Cache-Control: no-store`. Расширение должно получить файл через `fetch` с Bearer-заголовком и показать Blob URL. API-токен нельзя добавлять в URL. После удаления файла по сроку хранения `previewUrl: null` и `fileAvailable: false`; метаданные принятого снимка сохраняются.

## Подтверждение

`POST /drafts/{id}/confirm`, обязательный `Idempotency-Key` длиной 8–200 печатных ASCII-символов:

```json
{ "version": 14, "repeatConfirmed": false }
```

Используйте версию окончательного предпросмотра, который увидел пользователь. Сервер проверяет набор 4/9, все 13 хешей и наличие сохранённых файлов, затем одной транзакцией создаёт задачу и два поста. Ответ — принятая задача. После этого браузер не нужен для выполнения серверной части.

Повтор того же подтверждения возвращает ту же задачу; новый ключ для уже принятого черновика также не создаёт новую. Ключ привязывается к телу запроса; его использование с другим черновиком/телом даёт `409 IDEMPOTENCY_CONFLICT`. Повторная **галерея в новом черновике** требует `repeatConfirmed: true`; без него `409 REPEAT_CONFIRMATION_REQUIRED`. История учитывает в том числе отменённые задачи.

Принятая задача содержит `id`, `state`, UTC-время, неизменяемый `snapshot` с текстами и составом, отдельные `posts` и безопасный `last_error`. Серверные пути и секреты скрыты. Лимит сгенерированного текста — 4096 символов на пост. Постоянный Donut нельзя отключить запросом.

`posts[].last_error_details` содержит сохранённую диагностику именно этого сбоя: `method`, числовой `apiErrorCode`, HTTP-статус `httpStatus` и, при `VK_PHOTO_OWNER_MISMATCH`, `expectedOwnerId` / `actualOwnerId`. Поля необязательны, без ошибки возвращается `null`. Сообщения внешнего API, параметры запросов и токены не сохраняются. Успешная проверка подключения не стирает диагностику задачи; повтор или успешная сверка очищает текущую ошибку, а журнал попыток сохраняется. Для старой общей ошибки подробности могут отсутствовать.

При неверном ответе загрузчика `responseFields` показывает только JSON-типы полей `server`, `photo`, `hash`; их содержимое не сохраняется. Пустой результат загрузки получает `VK_UPLOAD_EMPTY` и автоматически повторяется. При старте новой попытки прежняя ошибка задачи и текущего поста очищается, при этом журнал не удаляется и уже сохранённые фотографии не загружаются повторно.

## Очередь, история и настройки

| Метод | Путь | Действие |
| --- | --- | --- |
| GET | `/status` | Версия, готовность хранилища, состояние интеграции VK, лимиты, ближайшие слоты. |
| POST | `/vk/check` | Проверка подключения VK без публикации; группа, причины блокировки и состояние готовности. |
| GET / PATCH | `/settings` | Настройки; изменение требует `version`. Доступны `timezone`, уникальные `slots` в `HH:mm`, `includeModel`. |
| GET | `/jobs` | Задачи и ориентировочные будущие слоты. |
| GET | `/jobs/{id}` | Снимок и результаты каждого поста. |
| POST | `/jobs/{id}/cancel` | Отменить до запуска/неопубликованный остаток; опубликованный пост сохраняется. |
| POST | `/jobs/{id}/retry` | Сразу продолжить передачу в отложенные ВК с будущим временем после исправления причины. |
| POST | `/jobs/{id}/reconcile` | Дополнительный маршрут сверки неизвестного результата через адаптер; в текущем запуске заблокирован до интеграции VK. |
| POST | `/queue/pause`, `/queue/resume` | Управление передачей; возобновление запускает её сразу, принятые ВК посты не меняются. |
| GET | `/history` | Завершённые, отменённые, частичные и требующие вмешательства задачи. |

`/jobs` и `/history`: `limit` (1–100, default 20), `offset` (default 0), `galleryUrl`, `state`, `from`, `to` (ISO 8601 UTC). Ответ: `items`, `total`, `limit`, `offset`. Полная очередь и результаты сохраняются в БД.

Состояния пары: `queued`, `publishing`, `retry_wait`, `partial`, `needs_attention`, `scheduled`, `completed`, `cancelled`. Состояния поста: `pending`, `uploading`, `ready`, `sending`, `scheduled`, `posted`, `retry_wait`, `unknown`, `failed`. `needs_attention` может содержать уже переданный обычный пост: всегда смотрите результаты обоих `posts`. Неопределённый результат нельзя отменять или слепо повторять.

После подтверждения фоновый обработчик сразу загружает фотографии и передаёт пару в отложенные ВК через `wall.post` с `publish_date`. Обычный пост получает ближайший свободный слот, Donut — минутой позже. Занятые минуты из `wall.get(filter=postponed)` и локальных операций обходятся; повторная передача уже принятого поста запрещена. Время сохраняется в `posts[].publish_at` (ISO 8601 UTC), до назначения — `null`. `scheduled` означает подтверждённую передачу в ВК, а не проверку фактического выхода на стене. История включает этот статус.

`queued` используется только для ещё не переданной задачи, например при паузе или недоступной интеграции. `POST /queue/pause` останавливает новые передачи; уже переданные посты выйдут силами ВК даже при выключенном сервере. Изменение расписания не переносит уже принятые ВК посты. `POST /jobs/{id}/cancel` отменяет только ещё не переданную часть пары, сохраняя принятые ВК записи; для целиком переданной пары возвращается `409 JOB_IN_VK`. Отменять и редактировать такие посты нужно в ВК. Повтор после временной ошибки выполняется не чаще раза в минуту с будущим временем; при частичном успехе сначала сохраняется исходное время Donut, если оно ещё доступно, иначе назначается следующий свободный слот с минутным сдвигом.
