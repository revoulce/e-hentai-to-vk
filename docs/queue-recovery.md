# Восстановление остановленных Donut-постов

Проверка 9 октября 2026 обнаружила 11 задач с сохранёнными ID обычных постов и ошибкой `VK_POST_VERIFICATION_FAILED`. Donut-посты этих задач ещё не создавались. В очереди также была одна новая задача. Работающий сервер сообщал `VK_AUTH_REQUIRED`, код API `5`.

ВК копирует фотографии владельца токена в сообщество с новыми ID. Обновлённый адаптер сверяет полноразмерные фотографии оригиналов и копий, а обработчик автоматически проверяет известные ID всех подходящих задач. После подтверждения обычного поста отправляется только Donut. Прошедшее время заменяется свободным будущим слотом.

## Обновление существующего Docker-сервера

Архив `ehvk-server-recovery.zip` содержит исходники, миграции и файлы сборки. Передайте его на сервер в `/tmp/ehvk-server-recovery.zip`. Из каталога существующей установки выполните:

```sh
cd ~/ehvk-server
unzip -o /tmp/ehvk-server-recovery.zip -d .
dc up -d --build --no-deps app
dc exec app node dist/src/vk-check.js
```

Здесь `dc` — уже настроенная на вашем сервере команда Docker Compose с конфигурацией VK и прежним файлом окружения. Архив не содержит секреты, `.env`, данные очереди или конфигурацию развёртывания. Не пересоздавайте токен API владельца и не удаляйте volume очереди.

Если проверка показывает код `5`, восстановите пользовательскую авторизацию ВК по [инструкции](vk.md). По одному этому коду нельзя определить, истёк токен или действует ограничение по IP. Токен должен работать с адреса сервера. После исправления авторизации выполните в расширении «Проверить подключение VK»; очередь должна быть без паузы.

После готовности VK сервер автоматически сверит сохранённые ID, затем передаст оставшиеся Donut-посты в отложенные. Результат пары станет `Передано в ВК`. Несовпадение содержимого или недоступность записи оставит конкретную задачу для ручной сверки без повторного создания обычного поста.
